# 03. 기술 설계

## 스택

| 항목 | 선택 | 이유 |
|---|---|---|
| 엔진 | **Phaser 3.90** | 2D 사이드스크롤·카메라·트윈·오디오가 기본 제공. 산나비식 픽셀 연출에 충분하고, VN 대화 시스템은 얇게 직접 짜는 편이 낫다. |
| 언어 | TypeScript (strict) | 스크립트 명령 타입을 컴파일러가 검사. |
| 번들러 | Vite 6 | 즉시 HMR, 정적 빌드 한 폴더. |
| 배포 | GitHub Pages (Actions) | push 만으로 웹 배포. 링크 하나로 테스트 공유. |
| 세이브 | localStorage | 단일 슬롯·챕터 체크포인트면 충분. 서버 없음. |
| 폰트 | Google Fonts (Noto Serif KR / Unbounded / Space Mono) | 원본 §9-2. |

**Ren'Py / Godot 를 안 고른 이유**: Ren'Py 는 걷기·트리거 같은 사이드스크롤 탐색이 어색하고, Godot 는 설치·에디터 의존과 바이너리 씬 파일 때문에 Claude Code 로 반복 작업하기 불편하다. 웹 스택은 브라우저에서 바로 검증되고 배포가 공짜다.

## 해상도 · 스케일

- 내부 캔버스 **960×540**, `Scale.FIT` + `CENTER_BOTH`. 픽셀아트 `pixelArt: true`.
- 픽셀 스프라이트 원본 32×48 등으로 그리고 게임 안에서 정수배 확대 권장. 배경은 960×540 그대로.
- 텍스트는 벡터 폰트(Phaser Text) — 저해상도 캔버스에 세리프 한글을 얹어도 읽히도록 540p 를 택했다 (360p 면 한글 세리프가 뭉개짐).

## 아키텍처

```
main.ts ── Phaser.Game ── [Boot] → [Title] → [Chapter(ch01)] → restart(ch02) → ...

Chapter 씬
 ├─ 월드: 바닥(TileSprite, static body) · 플레이어(Arcade sprite) · 트리거 · 카메라 follow
 ├─ DialogueBox (UI, scrollFactor 0, depth 1000)
 └─ ScriptRunner ─ StageHooks(= ChapterScene 자신) → bg/cg/bgm/show/hide/gotoChapter/endGame
```

### 책임 분리

| 모듈 | 하는 일 | 하지 않는 일 |
|---|---|---|
| `ScriptRunner` | 명령 순차 실행, 분기, 플래그, 입력 대기 | 그리기 |
| `DialogueBox` | 타자 효과, 이름표, 선택지 렌더·입력 | 진행 결정 |
| `ChapterScene` | 월드·트리거·카메라·연출 훅 구현 | 스토리 로직 |
| `SaveManager` | 플래그·체크포인트·읽음 기록 | 씬 전환 |
| `data/chapters/*.json` | **스토리 전부** | — |

스토리 텍스트는 코드에 한 줄도 없어야 한다. 텍스트 변경은 JSON 만 건드린다.

### 실행 흐름

1. `Boot`: `assets/manifest.json` 을 읽어 적힌 파일만 로드. 없는 키는 `makePlaceholders()` 가 Graphics 로 생성. 웹폰트 `document.fonts.ready` 대기.
2. `Title`: 새 이야기(이름 입력) / 이어서(세이브의 `chapterId`).
3. `Chapter.create()`: 체크포인트 저장 → 월드 구성 → 타이틀 카드 → `entry` 블록 실행.
4. `update()`: 스크립트 실행 중이면 이동 잠금. 아니면 좌우 이동 + 트리거 거리 검사. `auto` 트리거는 접근 즉시, 나머지는 `E`.
5. 블록 끝 → `runner.running=false` → 조작 복귀. `chapter` 명령 → 페이드 → `scene.restart({chapterId})`.

### 트리거 · 읽음 처리

- 트리거 id = `"<chapterId>:<label>"`. `once: true` 면 `SaveManager.seen` 에 기록되어 재방문 시 발동 안 함.
- 이어하기는 챕터 시작점부터 (위치 저장 안 함). 챕터가 짧으므로 충분.

### 플래그

- `set` / `choice.set` 으로 기록, `if` 로 분기. 문자열·숫자·불리언.
- 엔딩 플래그 `ending` ∈ `pity | respect | awe`. 에필로그 JSON 이 `if` 로 세 블록 중 하나로 점프.

## 에셋 파이프라인

```
public/assets/
  manifest.json     ← 로드 목록. 여기 없으면 플레이스홀더
  bg/<key>.png      960×540 (원본 프롬프트는 1920×1080 → 다운스케일)
  sprites/<key>.png 투명 PNG, 발끝이 하단 중앙 (origin 0.5,1)
  cg/<key>.png      960×540
  audio/<key>.mp3   30초~1분 루프
```

키 이름은 원본 §7·§8 파일명과 동일하게 (`forest`, `baelz_child`, `ch02_forest_child` …). 스프라이트 키는 `SPEAKERS[who].sprite` 로 연결.

## 앞으로 추가할 명령 (M1)

| 명령 | 용도 |
|---|---|
| `{ t: "fx", kind: "shake" \| "flash" \| "tint", ... }` | 8장 폭주, 13장 색 전환 |
| `{ t: "se", key }` | 효과음 |
| `{ t: "face", who, face }` | 표정 교체 (show 없이) |
| `{ t: "move", who, to }` | VN 모드 캐릭터 위치 이동 |
| `{ t: "unlock_chapter", id }` | 회상 해금 UI 용 (선택) |

## 테스트

- `npm run validate:script` — JSON 참조 무결성. CI 에서 build 전에 실행.
- `npm run typecheck`.
- 브라우저 수동 플레이. 개발 모드에서 `window.__game` 으로 Phaser 인스턴스 접근 가능 (콘솔 디버깅용).
- 향후: ScriptRunner 단위 테스트 (Vitest, StageHooks 를 목으로) — M1 에서 추가.

## 성능 · 호환

- 번들 ~1.5MB (Phaser 포함). 모바일 브라우저에서도 문제 없는 크기.
- WebGL 실패 시 Phaser 가 Canvas 로 폴백 (`Phaser.AUTO`).
- 터치 조작(가상 버튼)은 M5.
